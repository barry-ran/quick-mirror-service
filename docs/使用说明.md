# 使用说明

当前交付的是分阶段开发中的服务与客户端基础，不是可供用户完成群控的最终产品。PC、Android仍在独立开发分支联调；不要用测试服务替换原产品登录、收费或 ADB 版本。

## 已实现的服务调用边界

安装注册使用 HTTPS POST `/qm/v1/bootstrap/pc` 或 `/qm/v1/bootstrap/mobile`，请求为：

```json
{"install_public_label":"测试安装","idempotency_key":"11111111-1111-4111-8111-111111111111"}
```

示例 UUID 只展示格式，实际每次明确的新注册尝试必须生成新的随机 UUID。同一次请求丢包重试保持 key 和请求体不变。返回的 `registration_grant` 是敏感的一次性凭证，只供相应 Peerloom 安装注册 API 消费；不得截图、记录日志、导出设备列表或上传到业务分析系统。

- `IDEMPOTENCY_CONFLICT`：同 key 的角色/标签不同，不可偷偷修改请求后重试。
- `REPLAY_EXPIRED`：原尝试过期或上游凭证域改变，不自动生成新 key 重发。
- `OUTCOME_UNKNOWN`：服务端可能已完成签发，保留原尝试信息，不按新动作重复创建。
- `RESOURCE_EXHAUSTED`：临时请求负载预算已满，遵循 Retry-After；不是设备数上限。

完整响应定义见 [OpenAPI](../api/bootstrap.openapi.json)。原产品账号 token 不需要也不应转发给该安装注册接口。

## 尚未开放的使用流程

按 UUID 添加设备、多 PC 保存但单 PC 独占、投屏与连接分离、脚本上传/执行、权限状态、自定义 TURN 和批量导入/导出仍须客户端与服务整体联调。即使安装注册或单元测试通过，也不能声称上述流程已可用。最终功能与验收条件以 [产品 PRD](无ADB群控产品PRD.md) 为准。
