# 无 ADB 群控产品 PRD

版本：1.2｜日期：2026-10-29｜状态：甲方已整体确认，作为一期产品基线。

本产品面向机房批量运行 AutoX 脚本。在不启用 USB 调试、不依赖 ADB 的条件下，手机安装独立 APK，Windows PC 通过手机 UUID 跨局域网连接设备，支持多台手机同时投屏、群控和运行脚本，不设置设备数量产品上限，100 台和 500 台作为规模验证档位。操作体验以当前极限投屏 quick-desktop 为基准，仅修改权限变化、设备接入和跨网通信所必需的部分。

本文的功能范围和补充规则已由甲方确认。技术接口、模块拆分及实现任务见同目录技术开发文档和接口契约。技术参数是工程实现基线，不改变产品范围。

## 1 已确认的产品边界

| 编号 | 要求 |
|---|---|
| P01 | 独立分支开发，独立发布无 ADB 版本；不要求同一版本兼容旧 ADB 设备。 |
| P02 | PC 主要交付 Windows；macOS、Linux 确保编译通过，不据此承诺运行验收。 |
| P03 | APK 基于 AutoX 的 QuickMirror 集成 scrcpy 服务能力，参考 scrcpy-apk 概念验证。 |
| P04 | Android 最低版本已确认为 Android 8.0/API26。沿用 QuickMirror 的 ARM 设备支持目标；32 位 ARM 原生依赖需补齐，不得因现成 SDK 缺失而静默取消。 |
| P05 | iOS 后期开发，本期只保留平台能力差异的扩展边界，不交付 iOS。 |
| P06 | Peerloom 为通信底座；该项目属于可修改范围，移除本产品路径中的固定连接台数上限，不能把 100 或 500 写成产品上限。 |
| P07 | 尽量保留现有 PC 与 Android 音视频、控制协议；不为统一架构而重写可复用能力。 |

| P10 | 保留 PC 现有登录、账号、收费和产品授权机制；一期不接入现有账号 token 的服务端校验，不以该接口作为开发或发布前置条件。Peerloom 安装实例和会话校验保留。 |
| P11 | UUID 添加不增加密码、手机确认、配对审批等产品层验证。内部通信身份和凭证仍由系统处理，不要求取消 TLS 等传输保护。 |
| P12 | 只支持自定义 TURN 中继，不在一期新增整套业务平台私有部署产品能力。 |

## 2 使用流程

### 2.1 手机首次配置

1. 用户自行安装并打开 APK，无需连接 USB、开启开发者选项、无线调试或执行 ADB 授权命令。
2. 启动后优先展示授权引导，申请录屏授权，并引导开启无障碍；需要的权限不得伪装成已经授权。
3. 设备注册和在线状态上报不以录屏授权成功为前提。网络正常时，PC 能看到手机在线但待授权。
4. 手机展示固定 UUID，提供复制入口，展示网络、录屏、无障碍及当前 PC 连接状态。
5. 录屏和无障碍就绪后允许投屏、控制以及符合权限条件的 AutoX 任务。
6. 已确认：加入 QuickIME 首次配置引导，由用户在手机系统设置中手动启用并选择内置输入法。

固定 UUID 规则：应用重启、手机重启、网络变化、普通升级不改变 UUID；卸载重装或清除应用数据视为新安装实例。服务端不得把短期连接 ID 当作设备 UUID。恢复备份导致身份复制的行为需在技术阶段防止。

### 2.2 PC 添加设备

1. 沿用现有添加远程设备弹窗和布局，把分享码输入改为手机 UUID 输入。
2. 支持逐行输入或粘贴多个 UUID；支持设备列表文件导入。
3. 添加不需要手机确认或配对密码，但仍受现有 PC 产品登录及授权规则约束。
4. 添加后沿用设备列表、选择、分组、名称、编号、排序、网格和单机窗口交互。
5. 同一手机可被多台 PC 添加、保存；保存设备不等于建立控制连接。
6. 删除 PC 本地设备记录不卸载手机 APK，也不删除其他 PC 上的设备记录。

批量处理规则：空行忽略；UUID 格式错误逐项报告；重复 UUID 不重复建记录；部分成功保留成功项并报告失败原因；已注册但离线的手机允许保存并显示离线；未注册或不存在的 UUID 明确报错。服务不可达时不可误报 UUID 不存在。

### 2.3 连接和占用

已确认：同一手机同一时刻最多连接一台 PC；其他 PC 显示被占用，不自动抢占。主动断开后允许另一 PC 连接。异常掉线后通过连接失效检测释放占用。手机提供“断开当前连接”入口。UI 使用“连接/断开”，不建立跨离线永久保留的设备归属绑定。

需要同时申请同一设备时，只能有一台成功，不能因为并发请求出现两台 PC 都可控制。失效的旧连接不能在新连接建立后继续发送有效操作。

已确认：连接与投屏分离；停止画面或关闭单机窗口不释放设备连接，PC 和手机提供明确“断开”。主动断开后原 PC 不立即自动重连；异常断线失效后释放占用并允许自动恢复，但若另一 PC 已连接则不抢占。

占用失效检测的时间上界在技术方案和验收配置中明确，不采用永久占用。异常网络条件下须先使旧连接失效再允许新连接生效。

### 2.4 运行脚本

1. PC 选择 AutoX JS 脚本，对单台或所选多台设备运行。
2. 内部完成脚本下发并在 APK 中执行，不再使用 adb push、adb shell、am startservice。
3. 保留现有停止脚本、停止全部脚本入口及可用的批量操作体验。
4. 用户输入和脚本输入互相影响时沿用现有行为，不新增仲裁。
5. 截图操作没有所需权限时直接失败，不排队等待授权，不增加任务恢复和超时策略。
6. PC 断网、退出不触发新增的脚本暂停、取消、重跑或续跑逻辑。连接恢复不得自动重发执行请求而启动重复任务。
7. 只提供 AutoX 类型选择。BAT、Shell 和 ADB 命令脚本不支持；不做旧脚本迁移、不设计历史任务兼容界面。
8. 一期仅下发单个 JS 文件，不新增脚本目录打包、图片或模块目录自动传输；内部 JS 传输不作为通用文件上传入口。脚本自行访问既有资源仍受普通 APK 权限和路径约束。
9. AutoX 自身需要特殊权限的操作不因换用 APK 自动获得权限。失败应通过现有反馈入口或必要的错误信息可见，不伪报执行成功。

## 3 设备状态和授权恢复

在线状态、连接占用、投屏状态和权限状态是不同维度，不能用一个“离线”覆盖所有异常。界面可组合主状态和说明，无需新建独立仪表盘。

| 状态 | 用户应看到的含义 | 可执行行为 |
|---|---|---|
| 离线 | 手机未在线或不可达 | 保留记录；不可声称操作已送达 |
| 服务不可达 | PC 无法联系服务，设备状态无法确认 | 保留最近记录；不把所有手机误判为未注册 |
| 在线待授权 | 在线但录屏或控制权限缺失 | 显示具体缺失项；不伪造画面或输入成功 |
| 在线可连接 | 在线、未被占用 | 可发起连接 |
| 连接中 | 正在建立会话 | 避免重复建立同一连接 |
| 已连接 | 本 PC 拥有设备连接 | 按实际能力投屏、控制、运行脚本 |
| 被其他 PC 连接 | 手机已被其他会话占用 | 保留列表项；不抢占 |
| 连接失败 | 当前请求未成功 | 提供简洁原因和重试入口 |

权限撤销时，PC 保留设备并显示待授权，停止无效画面和相关操作。无障碍丢失不等于录屏必然失效，录屏丢失也不应自动停止所有不相关任务；调用需要权限的操作时按实际条件失败。

APK 在前台时发现授权缺失，发起系统授权或进入对应引导。位于后台且系统禁止拉起界面时，通过通知引导用户回到 APK，PC 持续显示待授权。用户拒绝后不得陷入反复弹窗；再次进入 APK 或主动重试时可以重新申请。

Android 的录屏会话授权不是永久授权。锁屏、用户停止录屏、进程退出等导致会话失效时必须遵循系统限制。不能承诺重启后自动恢复投屏，也不能把通知引导实现宣称为后台必然弹窗。

## 5 TURN 和服务

已确认：TURN 独立于业务服务。PC 可使用默认 TURN 或自建 TURN；手机无 TURN 配置页，使用当前 PC 会话的中继配置。不同业务/Peerloom 服务域之间不互联。

规则：PC 设置提供默认/自定义选择及地址、所需认证配置；保存不影响既有产品账号登录；新配置对新建连接生效。配置错误明确显示中继配置或连接失败，不提示手机重新授予录屏权限。自定义中继不可用时不得静默改用默认中继，避免违背用户的配置意图。

公网优先直连、必要时中继作为通信实现方向，不增加新的画质或任务策略。技术验收须能验证真实走了自建中继，不能仅用同一局域网直连结果代替。后台服务提供设备注册、UUID 查询、状态、单 PC 占用及建立会话所需业务能力；不新增计费后台或用户管理产品。

## 6 导入导出

导出字段：UUID、名称、编号、分组。支持另一台 PC 导入同批设备，不包含账号凭证、TURN 密码和脚本。

规则：导入按 UUID 去重；已有设备不重复创建，已有本地名称、编号、分组默认保留，新增设备应用导入信息；离线状态不阻止导出。无须导入另一台 PC 的数据库内部 ID。若产品未来支持服务域选择，导入不能把其他域的 UUID 自动当成本域设备连接。

## 7 规模和体验基线

最新确认：不设置同时连接设备数量上限，100 台不是封顶，支持 500 台及更多设备，实际能力由用户硬件和网络决定。不得在 UI、接口、存储或 Peerloom 设置固定台数门槛。验证采用 100、500 及可用的更高档位，持续有画面、可批量操作且各机可运行 AutoX；不能只验证列表能存储这些记录。单手机仅一台 PC 的规则不变。

资源队列仍须有界，遇系统资源不足应明确报错或背压，不能无限分配内存。分页、分批和并发启动调度是处理方式，不得变相截断总设备数。

当前 PC 配置中心的默认值为：网格分辨率档位 720、15 FPS、4,000,000 bit/s；单机窗口分辨率档位 1080、60 FPS、4,000,000 bit/s。保留现有含义、设置入口及参数传递行为，不把底层类的其他默认值误当产品默认值。100 路 4 Mbit/s 的配置量级为 400 Mbit/s，实际流量与内容和编码有关，尚未计协议开销；这只是容量说明，不是新增用户配置要求。

不要求甲方现在提供硬件和带宽。开发团队在验收时记录真实硬件、手机系统、配置及网络条件，不以测试设备不足新增连接上限；缺乏真实规模验证时明确记录未验证范围。实际显示帧率取决于内容与设备能力，不能用静态桌面或静态占位图假冒持续视频验收。

验收时长、稳定性阈值、异常释放时间上界见配套技术文档的工程基线；本文不代表已经通过性能验收。

## 8 产品验收场景

| 编号 | 操作 | 预期 |
|---|---|---|
| A01 | 关闭 USB/无线调试，手机和 PC 位于不同网络，安装 APK 后连接 | 无 ADB 初始化或辅助授权，投屏和可用操作成功 |
| A02 | 手机不授予录屏权限但保持联网 | PC 可添加并显示待授权；授权后可投屏 |
| A03 | 投屏中撤销录屏授权 | 状态更新；相关截图失败；引导重新授权，不显示旧帧为实时画面 |
| A04 | 无障碍关闭，录屏仍有效 | 明确控制权限缺失，不能假报输入成功 |
| A05 | 批量输入有效、重复、离线、错误 UUID | 按项反馈；有效项保留；不生成重复设备 |
| A06 | 两台 PC 同时连接同一手机 | 仅一台成功；另一台显示占用 |
| A07 | 当前 PC 或手机主动断开 | 另一台 PC 可连接；原 PC 不立即自动重连抢回 |
| A08 | PC 崩溃或网络断开后重新连接 | 占用有限期释放；无双连接；不自动重复启动脚本 |
| A09 | 使用自建 TURN 完成跨网会话 | 手机无需填 TURN；有证据证明指定中继生效 |
| A10 | 自定义 TURN 地址/凭证错误 | 可识别失败原因；不静默切换默认中继 |
| A11 | 导出设备到另一 PC，再次导入同一文件 | 所需元数据保留、无重复项、无秘密字段 |
| A12 | PC 下发 AutoX 单脚本，批量运行和停止 | 不调用 ADB；相同行为按现有执行模型完成 |
| A13 | 脚本截图时没有权限，或通过 API 提交 BAT/Shell | 前者直接失败；后者明确不支持 |
| A14 | UI、快捷键、拖拽、API、CLI 调用本期排除能力 | 无可执行旧 ADB 路径，不伪报成功 |
| A15 | 投屏与 AutoX 截图/识图同时使用 | 同一设备两项功能均可正常工作，不相互终止录屏会话 |
| A16 | 100/500 台及更高档位动态投屏并发脚本和批量控制 | 无固定台数拒绝；记录各档真实容量，不能只做模拟列表测试 |
| A17 | 升级 APK、重启手机、重启 PC | 普通升级/重启 UUID 不变；授权失效按规则显示和处理 |
| A18 | 验证登录、付费授权、分组、快捷聊天及窗口操作 | 除明确范围变更外保持现有行为 |
| A19 | 构建三个桌面平台及约定 Android ABI | Windows 运行验收；macOS/Linux 编译通过；APK 兼容矩阵有证据 |

| 占用释放 | 停止画面不释放；主动断开不自动抢回；异常失效释放后其他 PC 可连接。 |
| 脚本资源 | 只下发单 JS，不新增目录资源传输。 |
| AutoX 定时任务 | 一期不新增；原有定时任务仅保留仍支持的快捷操作。 |

甲方已整体确认：离线已注册设备可添加、批量部分成功、UUID 生命周期、导入冲突保留本地信息，以及 TURN 修改对新连接生效且不静默回退。

平台能力核实由技术阶段完成：剪贴板、音频、按键、应用列表和启动等，按已确认的“可可靠替代则保留，无可靠替代则移除”原则逐项记录结论；若影响核心鼠标控制、文本或脚本能力，必须回到甲方确认，不能以模糊的“按能力支持”直接宣布交付。
